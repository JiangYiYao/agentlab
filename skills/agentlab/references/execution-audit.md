# 某个版本在一个 case 上变差了，怎么查

运行或重评后，报告中每条分数都有「排查执行」链接，定位到 `runs/<run_id>/execution.html` 中的试验。页面按相同 case、命令组和重复编号配对当前组与对照组，并列分数、输入和产物。不自动从其他运行补一个对照，避免把不同条件的结果混在一起。

用户可以直接说“检查这个版本为什么在这个 case 上比对照差”。agent 应打开对应记录，解释具体差异和依据，并给出执行排查链接。失败、unknown 或影响推荐的较弱结果应在汇报时主动检查，不让用户先翻目录。

## 先分清发生了什么

先查看 `diagnostics.json` 的观测与证据缺口，再查对应原始材料。这份索引只整理可核对的信息，不生成因果结论，也不另开 LLM 裁判。

- **执行没有正常完成**：检查实际命令、退出码、stderr、超时或中止记录。评分或后处理失败与被测命令失败分别记录。
- **产物确实较差**：核对同一任务要求，看两组输出具体缺了什么、多了什么或做错了什么。代码任务看补丁和调用点，文本任务看事实和要求，数据任务看字段及数据内容；不能只复述低分。
- **测量不合适**：同时检查脚本日志和评分审计。检测规则误伤、裁判依据不足，都不能直接归因于被测 Skill。
- **单次数值较弱**：只有配置了 `measure.higher_is_better` 或单向通过条件（`>`、`>=`、`<`、`<=`），且保存的执行条件一致时才自动标注。不从 `quality`、`cost` 等名字猜方向，也不把单次差值当成统计结论。

配对条件核对包括原始任务、声明输入、命令组、执行包装脚本指纹、隔离与冻结配置、执行限制，不包含候选内容。候选差异另行展示。外部服务、随机性和未声明的输入无法靠这个检查保证一致。输入快照缺失、条件不同或对照未运行时，先说明限制。

## 再追查为什么

打开“与对照组比较输入和产物”，核对实际运行前的 Skill 内容及任务要求。再看轨迹中能验证的搜索范围、读取的文件、工具结果、错误、重试和子任务返回。命令 stdout 可能只是最终回答，不能默认当作完整过程。

结论分清：

- **已证实的问题**：具体输出或轨迹中的事实，并给出文件链接及位置。
- **可能原因**：与输入或步骤差异有关的解释，注明推测及支持、反对它的证据。
- **尚不能确定**：缺了哪些材料，或需要什么最小验证才能区分原因。

例如，补丁可以证明漏改了某个调用点；没有搜索轨迹时，就不能认定是搜索范围太窄或提前结束。不能编造模型未导出的内部推理。

实际排查后可把结论写到 `runs/<run_id>/diagnosis.md`，保留证据链接、待验证项和建议的最小验证，不覆盖原始评分及自动生成的 `diagnostics.json`。读取归档不需要重跑；新增执行、重评或改版沿用已授权的实验范围，不因为排查就自动开新一轮。

## 接入执行轨迹

AgentLab 不扫描外部 CLI 的全局会话目录。运行包装脚本应把本次会话中可导出的轨迹复制或写入自己的 `${trial_out}`，然后声明相对路径：

```yaml
trace:
  files: [trace/*.jsonl, trace/subtasks/*.json]
```

包装脚本可通过环境变量 `AGENTLAB_TRIAL_OUT` 获取目录。格式不绑定 CLI；JSONL、JSON 和文本都可保存并查看。优先导出带时间、事件类型、工具输入输出、错误及父子任务关联的记录。没有这些记录时标明未接入，不假造工具调用，也不要自行猜某个 CLI 的导出参数。

轨迹由执行器提供，其完整性和实际模型身份未经 AgentLab 独立验证。`trace.files` 只允许相对于试验输出目录的路径或 glob，不接受外部绝对路径。未匹配的声明会记录为缺失。没有配置时不自动采集全局日志；常规 stdout/stderr 仍会保存。

轨迹在执行结束、评分开始前归档，评分脚本改写同名产物不会覆盖原始轨迹。要把轨迹同时交给裁判，另在 `evidence.files` 声明；仅用于排查的轨迹不会因此自动加入裁判材料。改变轨迹配置会使执行身份变化；旧结果重评时不会凭空补采当时的轨迹。

## 保存范围和位置

新执行在启动命令前保存：

- 被测目录内容（排除 `.git` 和 `__pycache__`），以及原始、展开后的任务文本；
- `case.inputs` 明确声明的文件或目录；
- 能从执行命令识别到的包装脚本；解释器二进制只记录指纹；
- 执行条件快照、文件内容引用及缺失项。

这些内容写入 `executions/<id>/inputs/`，独立于可写工作目录，并通过内容存储共享相同文件。Git 仓库仍以冻结配置和补丁记录，不额外复制整仓作为输入快照。目录符号链接不递归采集，文件链接不跨出对应输入树；这些遗漏会列入清单。声明输入只记录开跑前的内容，不强制外部服务或执行器随后读取同一份文件。

`executions/<id>/trace/` 保存声明轨迹，`executions/<id>/outputs/runner/execution.json` 保存传入被测命令的实际 argv、cwd、提示词模式、耗时和退出码。外部 CLI 添加的上下文不在该记录内。

`runs/<run_id>/execution.html` 与 `diagnostics.json` 是可重新生成的阅读页和索引。清理工作区或缓存后依然可用，搬迁须保留整棵实验目录。页面仅比较有限长度的文本预览，原文件链接提供全部内容。旧记录没有运行前快照时会标明缺失，不用当前 Skill 填补历史。
